# Durable catalog synchronization

Scope: local-dl only, following the bot catalog handoff. Preserve queue/recovery cadence and full-snapshot POST /catalogUpdate contract. No bot changes or deployment.

1. Add SQLite singleton sync state and mutation triggers. Dirty generations commit atomically with meaningful files-table changes; unchanged last-seen updates do not dirty. Store captured payload/generation, retries, reconciliation requests and daily schedule. Tests cover rollback, no-op mutations and restart.
2. Replace permissive catalog mutation/scanning code with validated primary-video records and an all-or-nothing reconciliation. Scan both managed roots outside write transactions, verify root device/inode identities, fail on unreadable paths, and reject races with concurrent catalog changes. Validate new/changed files, omit staging/support files. Atomic application removes old paths and inserts moves together. Preserve entries when storage fails.
3. Build complete deterministic snapshots within one database transaction; never skip SQL errors. A single worker debounces 30 seconds with a 120-second ceiling, persists a snapshot before sending, retries identical bytes with exponential jittered backoff (30 seconds to 30 minutes), and pauses auth failures for 30 minutes with a concise notice. Acknowledge only verified 200 JSON with expected message/counts. Daily scheduling is persisted and advances only on successful full reconciliation upload.
4. Wire startup, explicit resync and manual scan into the worker; remove five-minute catalog upload only. Existing publication/removal hooks and repair moves update catalog atomically; external changes are found daily. Expose safe sync status through existing authenticated recovery status. Keep music playlist synchronization separate: this server catalog contract models movies/TV only.
5. Acceptance: fake-clock idle/daily tests; full add/remove/move snapshots; debounce bursts/max delay; persistent uncertain retry; mutation during blocked upload; serialized trigger races; storage-outage guards and invalid/incomplete files; strict auth/JSON acknowledgement. Run race suite/vet, native Mac tests, container build and review. Commit/push, deploy local-dl with rollback and verified status.

Structure: catalog.go keeps schema/read interfaces; catalog_mutations.go owns transactional records; catalog_reconcile.go owns scans/root identity; catalog_snapshot.go owns snapshot assembly; catalog_sync.go keeps wire types; catalog_sync_state.go and catalog_sync_worker.go own durable worker. Native Go tooling (gofmt, go test -race, go vet), no added dependencies; manual hotspot/transaction review ratchets existing code.
